# 📊 HYNM 在线甘特图（GitHub Pages 版 · 密码保护）

一个零依赖、纯前端的甘特图工具，支持 GitHub Pages 静态托管 + 多人协作编辑，并带**访问密码门**，防止公司外无关人员直接查看项目数据。

## ✨ 功能特性

- 🔒 **访问密码**：进入页面需输入密码（`HYNM2026`），密码错误无法查看任何数据
- 📅 **三种视图**：按天 / 按周 / 按月，一键切换
- ➕ **增删改查**：添加、编辑、删除任务，双击任务条或左侧卡片即可编辑
- 🔍 **搜索筛选**：按名称搜索 + 按阶段筛选
- 📈 **项目统计**：总任务数、已完成、进行中、整体进度
- 💾 **GitHub 同步**：配置 Token 后一键保存到仓库，刷新即同步
- 📥📤 **导入导出**：支持 JSON 文件备份恢复
- 🎨 **颜色区分**：不同阶段的任务用不同颜色标识
- 🔴 **今日线**：红色竖线标注当前日期位置

## 🔐 工作原理

```
打开页面 → 弹出密码遮罩 → 输入 HYNM2026
        → 浏览器用 SHA-256 计算输入哈希，与内置哈希比对
        → 一致：隐藏遮罩、加载 gantt-data.json、渲染甘特图
        → 不一致：提示"密码错误，请重试"，不加载任何数据
```

- 密码在 JS 中以 **SHA-256 哈希**形式存储（非明文），输入密码后由 `crypto.subtle` 实时计算比对
- 数据读写走**完全对称的明文 JSON 通路**：`saveToGitHub` 用 `JSON.stringify` + `btoa` 写入，`init` 用 `fetch + res.json()` 读取——彻底避免此前多轮"AES base64 层数不对称导致刷新仍是旧数据"的问题
- 未输对密码前，页面不渲染任何任务信息

## 🚀 部署教程

### 第 1 步：创建 GitHub 仓库
- 登录 GitHub → 右上角 **+** → **New repository**
- 名称填 `gantt-chart`，选 **Public**，点 Create

### 第 2 步：上传文件
- 把 `index.html` 和 `gantt-data.json` **两个文件**拖进仓库 → Commit

### 第 3 步：开启 GitHub Pages
- 仓库 → **Settings** → 左侧 **Pages**
- **Source** 选 `Deploy from a branch` → **Branch** 选 `main` + `/ (root)` → Save
- 等待约 1 分钟，访问 `https://你的用户名.github.io/gantt-chart/`

### 第 4 步：配置写入权限（实现"保存即同步"）
1. 打开 [GitHub Token 页面](https://github.com/settings/tokens)，生成 Token，勾选 **`repo`** 权限
2. 打开甘特图页面 → 输入密码进入 → 点右上角 **⚙️ 配置**
3. 填入用户名、仓库名、分支（`main`）、Token；**数据文件路径保持默认 `gantt-data.json`**
4. 之后点 **💾 保存修改并上传**，修改会写回仓库，刷新即用最新数据

## 🔑 修改访问密码

密码默认 `HYNM2026`，如需修改：

```bash
python3 change_password.py "你的新密码"
```

脚本会计算新密码的 SHA-256 哈希并自动替换 `index.html` 中的 `PASSWORD_HASH` 常量。把更新后的 `index.html` 重新上传仓库即可。

## 📝 使用说明

| 操作 | 方式 |
|------|------|
| 进入甘特图 | 输入访问密码 `HYNM2026` |
| 退出/锁定 | 点 🔓 退出，回到密码页并清空内存数据 |
| 添加任务 | 左侧面板填表 → 点添加 |
| 编辑任务 | **双击**甘特色条或左侧卡片 |
| 删除任务 | 悬停卡片 → 点 ✕ |
| 搜索/筛选 | 顶部搜索框 + 阶段下拉 |
| 切换视图 | 按天 / 按周 / 按月 |
| 保存到 GitHub | 点 💾 或 `Ctrl+S` |
| 导出/导入 | 📥 导出备份 / 📤 选择文件恢复 |

## 📌 注意事项

1. GitHub Pages 只支持**公开仓库**免费托管
2. GitHub Token 存在浏览器 localStorage，不会上传仓库；换浏览器/清缓存需重新配置
3. 多人同时编辑以最后一次提交为准，建议编辑前先刷新
4. 日期范围支持 2026 ~ 2099 年
5. **前端密码门可防"随手翻看/公司外无关人员"，但非银行级安全**；极度机密项目建议配合私有部署方案

## 🐛 本版修复说明

- **彻底解决"保存后刷新仍是旧数据"**：放弃此前多轮反复出错的 AES base64 方案，改为"SHA-256 密码门 + 明文 JSON 对称读写"。保存端（`JSON.stringify`→`btoa`）与加载端（`fetch`→`res.json()`）通路 100% 对称，杜绝编码层数不一致导致的回退到默认数据问题
- **保留原版排版/样式**：HTML 结构、CSS、三视图渲染逻辑均沿用用户确认的"好看版本"，未做破坏性改动
- 日期系统继续采用 UTC Ordinal（序天数）方案，彻底规避浏览器时区导致的任务条偏移
